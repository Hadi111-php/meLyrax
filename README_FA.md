# 🌧️⚡ بستهٔ «باران» و «صاعقه» — LyraX Clip Studio

دو افکت **کاملاً مستقل و ماژولار** که هر دو هم در پیش‌نمایش مرورگر و هم در رندر سروری
FFmpeg کار می‌کنند. حرکات هر دو **قطعی (seeded)** هستند: پیش‌نمایش = خروجی نهایی.

---

## ۱) چه چیزی داخل بسته است؟

```
lyrax-weather-pack/
├─ install.sh                              ← نصب خودکار روی مخزن
├─ studio/
│  ├─ lyrax-studio-pro-v4-weather.html     ← داشبورد کامل (تک‌فایلی، آمادهٔ اجرا)
│  └─ js/modules/
│     ├─ lyrax-storm.js                    ← ⚡ صاعقه + 🌧️ بارندگی (کلید L و تیک «باران پیوسته»)
│     ├─ lyrax-weather.js                  ← موتور قبلی (رعدوبرق هماهنگ با ضرب)
│     └─ lyrax-fx.js                       ← نسخهٔ ۱.۲ (صاعقه/باران از lyrax-storm.js)
└─ backend/
   └─ renderers.py                         ← رندرر FFmpeg با لایهٔ باران و صاعقهٔ تایم‌لاین
```

## ۲) نصب

```bash
cd 3-LYRAX-CLIP-STUDIO          # ریشهٔ پروژه (همان‌جایی که app.py هست)
bash /path/to/install.sh
```

اسکریپت خودش نسخهٔ پشتیبان می‌گیرد (پسوند `.bak.باران-و-صاعقه`) و این کارها را می‌کند:

1. `backend/renderers.py` را جای‌گذاری می‌کند.
2. `js/modules/lyrax-weather.js` و `js/modules/lyrax-fx.js` را می‌ریزد.
3. داشبورد `lyrax-studio-pro-v4-weather.html` را کنار داشبورد فعلی می‌گذارد
   (فایل قبلی را پاک نمی‌کند).
4. در `backend/models.py` سه کلید `rain_overlay`، `weather_lightning` و `layer_fx` را به
   فهرست فیلدهای اختیاری اضافه می‌کند تا این تنظیمات از JSON به رندرر برسند.

نصب دستی هم ساده است: چهار فایل بالا را سر جای خودشان کپی کن و همان یک خط مربوط به
`models.py` را خودت اضافه کن (در انتهای همین فایل توضیح داده شده).

## ۳) از کجا استفاده کنم؟

در داشبورد، پنل **«🎬 افکت‌های آماده»** درست زیر ردیف دکمه‌های پخشِ **تب ۱** است
(همان بالا، کنار بوم کلیپ؛ دیگر لازم نیست برای هر افکت به تب ۳ بروی):

| چیپ / دکمه | کار |
|---|---|
| ⚡ **صاعقه** | ثبت یک صاعقهٔ شاخه‌دار در «لحظهٔ پخش» یا در «زمان انتخابی» |
| 🌧️ **رگبار** | همان رخداد «باران طوفانی» (کلید R) با یک تپ |
| 🎆 **آتش‌بازی** / 🌊 **موج شوک** / ✨ **باران جرقه** / 💥 **فلاش** | بقیهٔ افکت‌های لایه‌ای (کلیدهای F/G/H/J) |
| ⚡ **برند** | ثبت یک سناریوی برند/امضا |
| 🌧️ **باران پیوسته: روشن/خاموش** | همان تیک «باران پیوسته روی تصویر» |
| ⚡ **صاعقه‌های خودکار: روشن/خاموش** | همان تیک «صاعقهٔ تایم‌لاین فعال» |
| ⏱ **چیپ زمان** (بالای پنل) | اگر از جدول یک ثانیه انتخاب کنی، همهٔ چیپ‌ها همان‌جا ثبت می‌شوند؛ با تپ روی چیپ لغو می‌شود |
| 🌧️ **باران پیوسته روی تصویر** (تیک) | باران روی کل کلیپ، مستقل از صاعقه |
| 🌧️ **باران طوفانی (R)** | یک رخداد ۸ ثانیه‌ای با زمان دقیق روی تایم‌لاین |
| ⚡ **ثبت صاعقه روی کلیپ (L)** | یک رخداد صاعقه روی تایم‌لاین |
| ⚡ **صاعقهٔ تایم‌لاین فعال** (تیک) | روشن/خاموش کردن رخدادهای صاعقه بدون پاک کردنشان |

> **📱 موبایل / بدون کیبورد:** کلیدهای میانبر (`L` صاعقه، `R` باران طوفانی، `F/G/H/J` بقیه) فقط با کیبورد
> فیزیکی (ویندوز/لینوکس) کار می‌کنند. روی گوشی و تبلت از چیپ‌های لمسی **تب ۱** استفاده کن — دقیقاً همان
> افکت‌ها را در همان ثانیه روی تایم‌لاین ثبت می‌کنند (همان تابعی که کلید میانبر صدا می‌زند).
> روی گوشی، بوم کلیپ بالای صفحه می‌آید (جمع‌وجور و ثابت) و پنل افکت‌ها درست زیر دکمه‌های پخش می‌نشیند
> تا هم تصویر کلیپ را ببینی، هم با انگشت خط بعدی را بزنی، هم افکت اضافه کنی.
>
> **⚡ صاعقه و 🌧️ بارندگی از ماژول `lyrax-storm.js` می‌آیند**
>
> * تیک **«🌧️ باران پیوسته روی تصویر»** عیناً همان `LyraxStorm.setRain(true/false)` است؛
>   خاموش/روشن کردنش کل بارش را (هم باران پیوسته و هم رخداد «باران طوفانی» با کلید R)
>   کنترل می‌کند و تنظیمات پنل (تراکم/سرعت/زاویه/شفافیت/طول/رنگ) هم به همان ماژول می‌رود.
> * چیپ **«⚡ صاعقه»** (یا کلید **L**) رخداد صاعقه را روی تایم‌لاین می‌گذارد و رسمش را همان ماژول
>   انجام می‌دهد: شروع از **گوشهٔ دقیق بوم**، midpoint displacement بازگشتی تا عمق ۱۶ (پس صاعقه دیگر
>   «خط صاف» نمی‌شود)، شاخه‌های جهت‌دارِ قطعی، سه‌بار کشیدن هاله/بدنه/هسته و فلاش کوتاه پشت صحنه.
>   برای سبک ماندن روی گوشی، هر صاعقه **یک‌بار** روی یک بوم مخفی کشیده می‌شود و بعد هر فریم فقط
>   با `drawImage` و آلفای متغیر روی تصویر می‌آید (همان جزئیات، بدون افت فریم).
> * ⚠️ **رعدوبرقِ هماهنگ با ضرب آهنگ** (پنل بالا با دکمه‌های «رعد قوی و کلفت» و
>   «رعد شاخه‌دار») کاملاً جدا و **دست‌نخورده** است؛ این ماژول به آن کاری ندارد.
>   صاعقه ≠ رعد: صاعقه یک رخداد زمان‌بندی‌شده روی تایم‌لاین است، رعد افکت هماهنگ با بیت. 

زیر همان پنل، بخش **«تنظیمات باران و صاعقه»**:
تراکم، سرعت، زاویهٔ قطره‌ها، شفافیت، طول قطره، رنگ باران، مبدأ صاعقه (متناوب/چپ/راست/وسط/تصادفیِ قطعی)،
تعداد شاخه‌ها و ضخامت صاعقه. رنگ و شدت نور صاعقه از همان پنل قدیمی «رعدوبرق هماهنگ با ضرب» می‌آید
تا دو جا تنظیم نشود.

هر دو افکت **مستقل**اند: می‌توانی فقط باران، فقط صاعقه، یا هر دو را هم‌زمان داشته باشی.

## ۴) مدت کلیپ — همیشه تا آخر آهنگ

قاعده ساده است:

* اگر آهنگی بارگذاری شده باشد، **طول کلیپ = طول خود آهنگ** (`audio.duration`).
* اگر آهنگی نباشد، تا **آخرین رخداد تایم‌لاین + ۲ ثانیه** (آخرین خط/افکت/برند/تصویر).
* دیگر هیچ‌جا عدد ثابت `۱۸۰` ثانیه استفاده نمی‌شود. مدت واقعی روی نوار پیشرفت
  (`m:ss / m:ss`) و در کارت دانلود (`مدت کلیپ: …`) نوشته می‌شود.

در عمل یعنی:

| کاری که می‌کنی | خروجی |
|---|---|
| «▶️ شروع ضبط زنده» را می‌زنی و هیچ کلیدی نمی‌زنی | ضبط تا آخر آهنگ می‌رود و **خودکار** بسته و آمادهٔ دانلود می‌شود |
| بین کار «⏹️ توقف» را می‌زنی | همان لحظه بسته می‌شود؛ کلیپ به همان مقدار رندر می‌شود (نه بیشتر) |
| «✨ رندر نهایی تمیز» را می‌زنی | تا آخر آهنگ رندر می‌شود و در پایان آهنگ خودکار تمام می‌شود |

> رندر تمیز دیگر به «لیریکس تایم‌دار» گره نخورده است؛ اگر فقط افکت/برند/تصویر داشته باشی هم رندر می‌شود.

## ۵) «⏱ زمان انتخابی» و افکت هر ردیف جدول

دو راه برای اینکه افکت را **دقیقاً** سر یک ثانیه بگذاری، بدون اینکه دنبال پخش بدوی:

1. **انتخاب زمان:** در جدول، کنار ثانیهٔ شروع هر ردیف دکمهٔ **⏱** هست. با زدنش آن ثانیه
   «انتخابی» می‌شود (بالای پنل افکت‌ها با رنگ زرد نشان داده می‌شود). از آن به بعد هر چیپی که بزنی
   (صاعقه، آتش‌بازی، برند، رعد…) در همان ثانیه ثبت می‌شود، نه در لحظهٔ پخش. با یک تپ دوباره روی
   چیپ، انتخاب لغو می‌شود.
2. **افکت هر ردیف:** ستون **«🎬 افکت این ردیف»** در همان جدول. برای هر خط/رخداد یک منوی افکت +
   دکمهٔ **➕** هست؛ با زدن ➕ آن افکت در ثانیهٔ همان ردیف ثبت می‌شود.

تمرکز روی دو نکته: **لایه‌ها با هم قاطی نمی‌شوند** و هر افکت با `t` خودش در `layer_fx` ذخیره می‌شود.

## ۶) بستهٔ کامل پروژه: JSON + ویدیو + اسکریپت MP4

بعد از ضبط، در کارت دانلود یک دکمهٔ بنفش اضافه شده:
**«📦 دانلود بستهٔ کامل پروژه (JSON + ویدیو + اسکریپت MP4)»**

یک فایل ZIP با اسم پروژه می‌گیری، مثلاً `اسم_آهنگ_bundle.zip` که داخلش:

```
اسم_آهنگ_project.json   ← همهٔ تایم‌ها + همهٔ افکت‌ها + تنظیمات باران/صاعقه + برند + اوورلی
اسم_آهنگ_clip.webm|mp4  ← خود کلیپ ضبط‌شده
make_mp4.sh             ← تبدیل فایل مرورگر به MP4 استاندارد (H.264 + AAC)
README.txt              ← همین توضیح کوتاه
```

فلسفهٔ این ساختار (همان که خواستی): **فقط تایم و نوع افکت ذخیره می‌شود؛ جزئیات شکل
(شاخه‌ها، درخشش، ضخامت، دانه‌های باران) لحظهٔ رندر ساخته می‌شود.** پس فایل پروژه کوچک می‌ماند و
پیش‌نمایش و رندر سروری به یک نتیجه می‌رسند.

تبدیل به MP4 در Termux:

```bash
pkg install -y ffmpeg
bash make_mp4.sh          # خودش فایل webm/mp4 را پیدا و به *_mp4.mp4 تبدیل می‌کند
```

> اگر مرورگرت MP4 را بومی ضبط کند (`video/mp4;codecs=avc1…`)، همان فایل مستقیم MP4 است و
> `make_mp4.sh` صرفاً دوباره رمزگذاری می‌کند. روی اندروید/کروم معمولاً WebM ضبط می‌شود و همان
> اسکریپت آن را به MP4 می‌برد.

## ۸) چرا پیش‌نمایش و رندر یکی می‌شوند؟

* هر دو موتور از یک PRNG قطعی (`mulberry32`) با همان seed و **همان ترتیب فراخوانی** استفاده می‌کنند.
* حرکت باران تابعی خالص از زمان است؛ دورهٔ پایه ۸ ثانیه و هر قطره در هر دوره تعداد صحیحی
  دور کامل می‌زند، پس پرش و اختلاف فاز ندارد.
* هندسهٔ صاعقه در پایتون **قطعه‌به‌قطعه** همان `buildBoltSegments` جاوااسکریپت است
  (توقف روی `displace < 2.5 || depth > 16`، انشعاب با احتمال ۰٫۳۸، زاویهٔ شاخه = جهت قطعه ± ۰٫۹۵
  رادیان، طول شاخه `0.25–0.67×` فاصله، پهنای شاخه `0.6×`) و همان سه‌پاس هاله/بدنه/هسته و
  همان منحنی پالس فلاش. با `node` + `python` روی چهار seed مختلف تست شده: اختلاف `< 1e-9`.
* در ASS، باران با `\move` عمودی روی یک خط موربِ ثابت رسم می‌شود (لایهٔ ۰ = پایین‌ترین لایه)
  و صاعقه/فلاش در لایهٔ ۳ روی همه‌چیز.
